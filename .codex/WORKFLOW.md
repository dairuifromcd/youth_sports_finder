# Youth Sports Finder 项目多 Agent 工作流

本目录仅属于当前仓库，不安装个人/全局 Agent，不改变全局信任、权限、模型、MCP 或安全设置。

## 加载与新 Chat

在当前 Youth Sports Finder 项目根目录开始新 Codex Chat，明确要求 Main 调用自定义
`developer`、`qa`、`uat`。角色以各 TOML 的 `name` 为准，不是普通子代理的显示名称。
项目必须已受信任才会加载项目配置；如果被忽略，停止并报告，不自动修改全局 trust。
已开始的 Chat 不保证热加载新增角色。新 Chat 中应先进行加载检查，再执行任务。

示例：

> 按本项目 AGENTS.md 和 .codex/WORKFLOW.md，调用实际自定义 developer、qa、uat
> 执行已批准的 TASK-xxx。先确认角色加载，最多修复三轮；保留独立验证证据，阻塞则报告。

加载检查须保留实际 spawn 的角色名/agent ID，并要求子代理返回其配置中的角色加载标识。
Main 不能在验证提示中给出标识答案，不能仅按任务名称“模拟角色”。三个文件通过 TOML
解析或普通 agent 读到文件都不证明自定义角色已加载。

## 执行闭环

1. Main 读取批准任务，确认范围、验收标准、产物目录和必要权限。
2. Developer 实现和自检；只在批准范围内编辑。
3. QA 独立检查和执行相关自动化验证，报告可复现缺陷。
4. QA 通过且必要审批获准后，UAT 在 Main 指定范围内独立进行真实浏览器操作、截图、视觉与基本可访问性检查。
5. 验证发现产品缺陷则交回 Developer；针对实际修改重新进行相关 QA 和 UAT，最多自动修复三轮。
6. UAT 完成必需的浏览器关闭与收尾后，Main 独立核对关闭证据，再根据业务测试和收尾各自的实际结果给出最终结论。全部必要项目有证据才可最终 Pass；任一 Fail/Not Verified 均如实保留。

权限/工具阻塞或三轮后仍失败，停止新的测试/修复步骤并报告，按下述规则安全收尾，不降低标准；权限阻塞不能当作产品缺陷擅自修复。
简单、低风险任务可按任务风险减轻流程，不自动扩大任务或启动后续任务。

## 交互式浏览器审批

优先使用支持交互式审批的 Codex 会话。Main 先确认已有明确授权是否覆盖本次目标和操作；
已获批范围不重复申请，访问目标或操作超出授权时必须先取得新增批准。

浏览器工具需要审批时，Main 必须事先说明：

- 指定的本地测试网站，包括协议、主机、端口及允许路径；不得延伸到无关网站、个人标签或其他项目。
- 操作范围，包括搜索、点击、地图拖动/缩放、滚动、键盘、视口调整、截图及项目内证据位置。
- 可能的项目外影响，例如临时进程、缓存、日志、会话记录、系统临时文件及网络请求。
- 具体风险、恢复/关闭方法，以及可行的仅项目内替代方案。

由用户明确批准后，再通过当前会话支持的机制完成工具所需审批。用户授权和工具的运行时
审批是两个环节；有聊天授权不代表工具策略已改变。审批成功后，UAT 才访问 Main 指定的
Youth Sports Finder 本地目标并执行已批准操作。

审批申请失败、工具拒绝或权限不足时，UAT 停止新的测试步骤，保存实际错误并报告 Not Verified，
Main 记录阻塞与未执行项；已建立的测试会话仍在下述安全条件下收尾。不得改全局设置、
关闭安全保护、切换工具绕过审批或伪造结果。
改写角色指令不能自动解决运行环境中的 approval policy is never 阻塞。

## 浏览器关闭与收尾

浏览器关闭与清理是每轮 UAT 的必需步骤。浏览器操作和必要截图保存完成后，UAT 应优先
通过项目 `ysf_browser` 的 `browser_close` 关闭已确认归属本轮的测试会话，保存实际返回，
再进行本地截图复核及最终报告整理。操作中的必要证据仍须及时保存，不能等最终报告时补记。

如使用总时间窗口，Main 在总预算内为关闭及结果确认预留至少 **20 秒**，明确测试截止和
总截止；UAT 每次新测试调用前检查剩余预算。剩余时间不足以完成该操作并保留至少20秒，
或已进入收尾预留时段时，停止新测试，立即转入收尾。Main 的监控在测试截止时应优先
安排收尾，不能把测试截止直接当作中断整轮的时点；关闭调用仍须有可执行的短时上限，
总硬截止仍有效，到期仍未完成时停止等待并记录 Not Verified，不在总截止后追加收尾时间。

即使业务测试失败或部分步骤阻塞，只要本轮测试会话已经建立、操作仍在已批准范围内，
且安全、工具可用并可受控中断，UAT 仍应尝试 `browser_close`。停止测试不等于放弃安全收尾；
收尾不得恢复测试或绕过审批。若未建立会话，不为收尾新建会话；若工具或权限阻塞使关闭
无法安全执行，记录原因与未完成状态，停止进一步调用。

UAT 必须保存关闭目标、实际返回及完成状态。关闭失败保留原始错误；无返回、被中断或
无法尝试时如实记录，关闭与清理均为 **Not Verified**。不得仅因已发送关闭请求、代理已中断
或业务测试通过就声称清理成功。

仅关闭已确认归属本轮的测试浏览器会话。禁止使用 `pkill Chrome` 等方式终止未知浏览器
进程或影响个人 Chrome 会话。测试浏览器会话关闭与 MCP 服务进程退出必须区分；不要求
为了结束 UAT 强制终止 MCP 服务。`browser_close` 返回仅支持其实际确认的关闭范围，
不得推断所有 Chrome 进程、Socket 或临时文件均已退出或清理。

Main 必须在最终报告中独立核对关闭调用的实际返回及目标归属，并分别列出业务测试结果、
浏览器关闭与清理结果及未完成项，不能只采信 UAT 的通过结论。缺少成功关闭证据时保留
Not Verified，不得报告完整生命周期 Pass。独立确认也须遵守既有授权，不扩大检查范围。

2026-11-04 本次修订仅更新收尾规范并执行静态检查；不代表此前遗留浏览器已经关闭，
也不代表新角色指令已热加载或完成运行时验证。

## 实际权限与边界

三个角色继承父会话的沙箱、批准策略、模型、提供方和 MCP 工具。当前官方格式不允许在
角色文件中覆写 `sandbox_mode`、`approval_policy`、`model_provider` 或 `mcp_servers`。
因此 QA/UAT 的不编辑规则是指令约束，**不是**独立的技术只读隔离。需要只读沙箱时，
必须由父会话在平台支持范围内设置；需要写证据/构建缓存时，事先说明相应例外。

项目配置启用 agents、将同时运行的子代理上限设为三，并注册仅本项目的 `ysf_browser`，
不改变父会话权限。非 shell
浏览器/MCP 工具仍遵守各自访问控制，不能把 shell 沙箱误认为浏览器的完整隔离。

`ysf_browser` 复用已有完整 Playwright core 缓存，不调用 npm、不安装或更新包；若缓存
缺失/不兼容则停止。浏览器使用独立内存会话并保留自身 sandbox，默认文件访问仍限于
工作区。缓存路径和 Chrome 路径属于当前 Mac 环境，迁移或缓存清理后须重新验证。
本机旧的全局 Playwright MCP 缓存缺失依赖，试运行通过临时 CLI 参数禁用该旧 MCP；
未改动全局文件。既有全局 MCP 如涉及安装或项目外影响，未来运行前仍须检查授权。

所有源文件和数据修改限定当前仓库；禁止改动全局配置/其他项目。浏览器、CLI、服务器
可能写入项目外的缓存、日志、会话或临时目录，须先列明影响、风险、恢复方式和替代方案，
获批后才能运行。不能为工作流关闭沙箱或自动扩大权限。

Main 为每项任务指定独立的项目内证据目录，例如 `output/workflow/<日期>/<任务>/`；截图
使用明确的任务路径和文件名，避免覆盖已有记录。实际 MCP 默认输出/临时路径以现有配置为准，
不能假定其会随任务日期自动变化。保留原任务历史结论，新的验证结果单独报告。
